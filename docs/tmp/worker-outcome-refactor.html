Worker outcome refactor

Base: main at 2fda60d3 (PR #32 merged, typecheck clean). Work branch refactor/worker-outcome in the worktree ../v1_hearted-audit, holding the uncommitted dead-code cleanup.

One sentence. The plan's WorkerOutcome union is right, but the root problem is that one fact is written to three stores in three writes, and recovery exists only to patch the gaps. Make the finalize one transaction that writes all three, and the rest of the plan gets simpler.

2 · Recommended shape

Why one transaction

A finalized job always has its measurement. Recovery's "no measurement ⇒ conservative failure" branch is then reachable only for dead-lettered jobs. Bug A shrinks from "success recorded as failure" to "settlement delayed one sweep".

Cost: the measurement insert becomes load-bearing. It already is — recovery depends on it. A failed insert now rolls back the finalize and takes the retry path instead of a log.warn.

Why still re-read on retry

Keep the isOwnWrite re-read from platform/jobs/lifecycle.ts so the runner proceeds to step ③ immediately instead of waiting for the sweep. Predicate must include error text, as the lifecycle comment notes: a dead-letter also leaves this claim's attempts on a failed row.

The union

type WorkerOutcome =
  | { workflow: "enrichment"; kind: "completed"; requestSatisfied: boolean;
      newCandidatesAvailable: boolean; counts: Counts }
  | { workflow: "enrichment"; kind: "blocked"; counts: Counts }
  | { workflow: "enrichment"; kind: "failed"; error: string; counts: Counts }
  | { workflow: "match_snapshot_refresh"; kind: "published"; snapshot: { id: string; isEmpty: boolean } | "unchanged" }
  | { workflow: "match_snapshot_refresh"; kind: "superseded" }
  | { workflow: "match_snapshot_refresh"; kind: "failed"; error: string };

// pure, exhaustive switches — one file, one test file
finalStatusOf(o)              // "completed" | "failed"
accountEventsOf(o)            // 0..2 WriteAccountEventInput
measurementOf(o)              // { outcome: string; details: Json }  — strings frozen (see §4)
changeOf(o)                   // LibraryProcessingChange
workerOutcomeFromMeasurement(row)  // zod decode; accepts legacy rows incl. outcome="blocked"

counts comes from the run result, not from job.progress. That fixes the stale-counts event as a side effect; call it out as a behavior change.

Retry rule, no flag

const retry = finalStatusOf(outcome) === "completed" ? FINALIZE_RETRY : { maxRetries: 0 };
const r = await withRetry(() => finalizeJob(ctx.job, outcome), retry);
if (Result.isError(r))         return finalStatusOf(outcome) === "completed" ? finalizeFailed(ctx, r.error) : /* log, continue */ …;
if (r.value === "lease_lost")  return leaseLost(ctx);
return settle(ctx, changeOf(outcome));
